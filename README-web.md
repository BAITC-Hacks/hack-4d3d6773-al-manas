# Граф денег — веб-сайт для анализа сети переводов

Полноценный локальный сайт: собственный HTML/CSS/JavaScript-интерфейс и Python API. Не Streamlit и не desktop-приложение. Не требует CDN, аккаунтов, внешних API, GPU или платных сервисов. Интерфейс адаптирован к телефону и компьютеру.

## Установка и запуск

Нужен Python 3.11+ (рекомендуется 3.12). Из папки `money-graph`:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m src.server
```

Откройте http://127.0.0.1:8000. Без параметров загружается **синтетический** пример: 65 узлов, включая изолированный; это не результаты хакатона. На macOS/Linux используйте `.venv/bin/python` вместо `.venv\Scripts\python`.

Загрузка настоящих данных: кнопка «Загрузить данные» → выбрать три Parquet → «Построить граф». Или:

```powershell
.venv\Scripts\python -m src.server --data-dir data --port 8000
```

## Воспроизводимый запуск Parquet → CSV

```powershell
.venv\Scripts\python -m src.pipeline --data-dir data --output-dir output
```

Создать синтетический набор и результаты отдельно:

```powershell
.venv\Scripts\python -m src.pipeline --demo --data-dir demo-data --output-dir demo-output
.venv\Scripts\python -m unittest discover -s tests -v
```

`--demo` записывает синтетические Parquet в указанную папку; используйте отдельную `demo-data`, чтобы не перезаписать настоящие файлы. Флаг синтетических данных сохраняется в `analysis.json`; CSV соответствуют строгой схеме и не содержат дополнительного столбца.

## Входы и выходы

В исходных материалах были только требования, без README организаторов и настоящих данных. Используется точная схема из предоставленного текста:

| Файл | Поля |
|---|---|
| nodes.parquet | gid, depth, is_seed |
| edges.parquet | src, dst, sum_kzt, n_tx, depth |
| transactions.parquet | src, dst, date, sum_kzt |

`gid`, `src`, `dst` приводятся к строкам; gid уникален. `is_seed` — bool или 0/1. Суммы конечные и неотрицательные; depth — целое ≥ 0, n_tx — целое ≥ 1; даты разбираются pandas. Пустые обязательные значения и неизвестные концы рёбер отклоняются. Повторные рёбра агрегируются суммой сумм и числа транзакций. Сохраняется каждый узел, даже без рёбер. edges — источник графа, transactions — источник временной динамики; их согласованность по суммам не предполагается и автоматически не сверяется.

| Выход | Столбцы |
|---|---|
| nodes_roles.csv | gid, role, role_score, cluster_id, priority_score, evidence |
| clusters.csv | cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis |
| top_nodes.csv | rank, gid, role, priority_score, why |

CSV: UTF-8 BOM, разделитель запятая. top_nodes: до 50 узлов, не менее 20, если в наборе есть 20. Экспорт из сайта относится ко всему набору, а не текущему фильтру. `analysis.json` содержит метрики и сериализованную сеть.

## Правила ролей

Конфигурация: `config.json`. Один узел получает первое подходящее правило в следующем порядке:

1. **coordinator**: нормированное посредничество ≥ 0,12 и суммарная степень ≥ 4; score = min(1, посредничество / 0,24).
2. **consolidator**: минимум 4 отправителя и их больше, чем получателей; score = min(1, число отправителей / 8).
3. **distributor**: минимум 4 получателя; score = min(1, число получателей / 8).
4. **transit**: оба потока > 0, меньший / больший ≥ 0,7; score равен этому отношению. Исключены seed и depth ≥ 4.
5. **terminal**: вход > 0, выход / вход ≤ 0,15; score = 1 − выход / вход. Исключены seed и depth ≥ 4.
6. **peripheral**: иначе; score = 0 (нет положительного совпадения с более определённой ролью).

Метрики используют уникальных контрагентов по направлениям. Петли сохраняются и учитываются как входящие и исходящие рёбра. Посредничество — по невзвешенным кратчайшим путям, с выборкой min(128, N), seed=42. Сумма перевода не трактуется как длина пути.

Приоритет = 0,35 × (вход+выход)/max потока + 0,25 × степень/max степени + 0,30 × посредничество + 0,10 × is_seed. Оценки ограничены диапазоном 0–1 и округлены до 4 знаков. Это эвристики, не валидированные вероятности; размеченных ролей нет. Evidence содержит реальные метрики конкретного узла, до 200 символов.

## Кластеры

Louvain, seed=42, неориентированная проекция с весом `w(a,b)+w(b,a)`; рёбра нулевой суммы в проекции пропускаются, узлы сохраняются. Перед построением узлы и рёбра сортируются. Кластеры сортируются по минимальному строковому gid, затем нумеруются с 1; изоляты имеют собственный кластер. Для строгой воспроизводимости между машинами фиксируйте версию NetworkX (проверено с 3.7). `sum_kzt_internal` — сумма исходных агрегированных ориентированных рёбер с обоими концами в кластере; каждое направление учитывается один раз. Гипотеза кластера осторожная, шаблонная: не утверждает виновность или организационную структуру.

## Интерфейс

Поиск по gid, фильтры ролей/кластеров, переключение раскраски, масштабирование, перетаскивание фона, карточка узла, просмотр его соседей, таблица приоритетов, карточки кластеров, временная динамика и скачивание трёх CSV. При N > 300 по умолчанию показываются соседи приоритетного узла. Для доступности: клавиатурный фокус, Enter на узлах/строках, `/` для поиска, системные шрифты, reduced-motion.

## Ограничения и масштабирование

Сервер привязан к 127.0.0.1 и предназначен для одного аналитика: текущий загруженный набор общий для вкладок, хранится в памяти и сбрасывается при перезапуске. Это локальный MVP без авторизации и production-инфраструктуры. Файлы из интерфейса до 45 МБ суммарно. Загружайте доверенные Parquet. Топология нарисована детерминированной раскладкой по кластерам; расстояния на карте не являются финансовой метрикой.

На миллионе узлов нужны пакетное чтение Arrow/DuckDB, компактные массивы/CSR, igraph или распределённые алгоритмы, приближённое посредничество и асинхронные задания с кэшем. Не передавать полный граф в браузер: API соседей и агрегатов, серверная пагинация, WebGL и уровни детализации. Текущие Python-объекты NetworkX и SVG на такой масштаб не рассчитаны.

Настоящих файлов датасета нет. Корректность конкретных ролей, качество кластеров и время на реальном наборе 2248/3119/4840 не проверены. Синтетические проверки не заменяют валидацию на реальных данных.
